## 1. Overview and Architecture

The Track A multi-dispenser dataset provides high-fidelity, reproducible synthetic queue data capturing multi-server queue dynamics at CNG filling stations.

Unlike the legacy single-server CSV ([`backend/data/synthetic/noqueue_simulated_data.csv`](file:///Users/lavanyagosain/Desktop/NoQueue/backend/data/synthetic/noqueue_simulated_data.csv)) which approximated each station as an aggregate $M/M/1$ queue with static waiting formulas ($\text{wait} = \text{queue} / \text{service\_rate}$), the Track A dataset:
1. Models each physical dispenser as an independent server with its own active vehicle and waiting line.
2. Implements station-level vehicle arrivals with dynamic Join-Shortest-Queue (JSQ) tie-breaking and roadway balking.
3. Uses the 2025 Arena CNG case-study empirical service distributions:
   - **Line 1 (Beta):** $233 + 179 \times \text{Beta}(0.904, 1.03)\text{ seconds}$ (Mean $\approx 316.5\text{s}$, min $233\text{s}$).
   - **Line 2 (Triangular):** $\text{Triangular}(239, 350, 295)\text{ seconds}$ (Mean $\approx 294.7\text{s}$, mode $295\text{s}$).
4. Separates periodic station state snapshots from granular, vehicle-level event telemetry.
5. Tracks exact simulation timestamps (seconds and ISO-8601) to compute actual waiting and service durations.

## 2. Core State and Event Invariants

The dataset enforces the following mathematical invariants:
1. **Total Occupancy Decomposition:**
   $$N_{\text{total}}(t) = N_{\text{waiting}}(t) + N_{\text{active}}(t) = \sum_{j=1}^c k_j(t) + \sum_{j=1}^c b_j(t)$$
2. **Dispenser Server Capacity:**
   $$b_j(t) \in \{0, 1\} \quad \forall j \in \{1, \dots, c\}$$
   Each physical dispenser serves at most one active vehicle at any given instant.
3. **Unique Assignment:**
   Every accepted arriving vehicle is assigned to exactly one dispenser via Join-Shortest-Queue ($N_j = k_j + b_j$).
4. **Temporal Ordering:**
   For every vehicle completing service:
   $$t_{\text{arrival}} \le t_{\text{service\_start}} < t_{\text{service\_completion}}$$
5. **Exact Duration Accounting:**
   - Actual waiting duration: $\Delta t_{\text{wait}} = t_{\text{service\_start}} - t_{\text{arrival}}$.
   - If assigned to an idle dispenser ($b_j = 0$): $\Delta t_{\text{wait}} = 0.0\text{ seconds}$.
   - If assigned to a busy dispenser ($b_j = 1$): $\Delta t_{\text{wait}} > 0.0\text{ seconds}$ upon transition to service.
   - Actual service duration: $\Delta t_{\text{service}} = t_{\text{service\_completion}} - t_{\text{service\_start}} > 0.0\text{ seconds}$.
   - Total system duration: $\Delta t_{\text{system}} = \Delta t_{\text{wait}} + \Delta t_{\text{service}}$.

## 4. File 1: Periodic State Snapshots Schema (`multidispenser_state_snapshots.csv`)

Recorded at the end of every simulated minute for each station. Total rows: $960$ ($4\text{ stations} \times 240\text{ minutes}$).

| Column Name | Data Type | Units / Format | Nullable | Description |
| :--- | :--- | :--- | :---: | :--- |
| `snapshot_id` | String | Format: `SNAP-S{id}-{step}` | No | Unique snapshot identifier (e.g. `SNAP-S1-0005`) |
| `timestamp_iso` | String | ISO-8601 (`YYYY-MM-DDTHH:MM:SS+00:00`) | No | Simulated wall-clock timestamp (starts `2026-11-15T08:00:00Z`) |
| `simulation_time_seconds` | Float | Seconds ($60.0, 120.0, \dots$) | No | Cumulative elapsed simulated seconds from start of run |
| `simulation_time_minutes` | Integer | Minutes ($1, 2, \dots, 240$) | No | Cumulative elapsed simulated minutes |
| `step_index` | Integer | Integer ($1, 2, \dots, 240$) | No | 1-based simulation step index |
| `station_id` | Integer | ID ($1\text{--}4$) | No | Demonstration station identifier |
| `station_name` | String | Name | No | Station name (e.g. `Green Fuel CNG Station`) |
| `num_dispensers` | Integer | Count ($2$ or $4$) | No | Number of independent physical dispenser channels |
| `demand_profile` | String | Category (`LOW`, `MODERATE`, `HEAVY`) | No | Configured station demand profile |
| `nominal_arrival_rate_per_min`| Float | Vehicles / minute | No | Base arrival rate modulated by sinusoidal time curve |
| `effective_arrival_rate_per_min`| Float | Vehicles / minute | No | Effective rate after applying roadway balking factor |
| `total_vehicles` | Integer | Vehicle count | No | Total station occupancy: $N_{\text{total}} = N_{\text{waiting}} + N_{\text{active}}$ |
| `waiting_queue_length` | Integer | Vehicle count | No | Vehicles strictly waiting in line: $N_{\text{waiting}} = \sum k_j$ |
| `vehicles_being_served` | Integer | Vehicle count | No | Vehicles currently being fueled: $N_{\text{active}} = \sum b_j$ |
| `dispenser_active_counts` | String (JSON) | Array of integers `[0, 1]` | No | Per-dispenser active flag (e.g. `[1, 1]`) |
| `dispenser_waiting_counts` | String (JSON) | Array of integers | No | Per-dispenser waiting count (e.g. `[2, 1]`) |
| `dispenser_remaining_service_seconds` | String (JSON) | Array of floats (seconds) | No | Remaining service time for active vehicle on each dispenser |
| `potential_arrivals_in_step` | Integer | Count | No | Total vehicle arrivals generated during this minute |
| `accepted_arrivals_in_step` | Integer | Count | No | Arrivals that joined the station queue |
| `balked_arrivals_in_step` | Integer | Count | No | Arrivals that diverted due to roadway congestion |
| `vehicles_served_in_step` | Integer | Count | No | Total vehicles that completed fueling during this minute |
| `estimated_incoming_wait_minutes` | Float | Minutes | No | Multi-dispenser expected wait for an incoming vehicle (JSQ-weighted) |
| `congestion_level` | String | Category (`LOW`, `MEDIUM`, `HIGH`) | No | Classification based on wait ($\le 10\text{m}$, $10.1\text{--}20\text{m}$, $>20\text{m}$) |
| `crowd_level` | String | Category (`LOW`, `MODERATE`, `HIGH`) | No | Classification based on queue ($\le 5$, $6\text{--}12$, $>12$) |
| `is_synthetic` | Boolean | Boolean (`True`) | No | Explicit synthetic provenance flag |
| `provenance` | String | Identifier string | No | Generating simulator signature |
| `random_seed` | Integer | Seed integer | No | Station-specific simulation seed |

## 7. How to Reproduce the Dataset

Execute the standalone generation script using the project's virtual environment:
```bash
PYTHONPATH=backend backend/venv/bin/python3 backend/data/synthetic/generate_multidispenser_data.py
```

Execute the validation test suite:
```bash
PYTHONPATH=backend backend/venv/bin/python3 -m unittest backend.test_multidispenser_dataset
```
